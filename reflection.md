# Reflection

Building the Integer Overflow Lab helped me understand integer overflow more concretely because I had to turn an abstract definition into something a learner can manipulate. Instead of only reading that fixed width arithmetic “wraps around,” I could represent the result as a limited number of bits and compare the unsigned and signed interpretations of the same bit pattern. The example `127 + 1 = 10000000` made the two's complement behavior especially clear, the mathematical result is 128, but signed 8-bit storage interprets those same bits as -128.

My workflow was AI-assisted but iterative. First, I chose integer overflow because it could be demonstrated safely with a small browser application and did not require external libraries. I then used AI to help plan the interface and generate an initial self-contained HTML file. I reviewed the generated logic, focusing on the modulo calculation, signed two's complement conversion, and the visual representation of the bits. I also added a short quiz so the application tests understanding instead of only displaying output.

The most useful part of the process was connecting the code to the concept. The JavaScript calculation `result mod 2^n` mirrors the idea that an n-bit unsigned value has only `2^n` possible patterns. Implementing the signed conversion also reinforced that signedness is an interpretation of the stored bits rather than a completely different set of bits. The project showed me how AI can speed up prototyping while still requiring human review. I had to decide what concept the visualization should teach, check whether the behavior was correct, and make sure the application stayed within the assignment's educational scope. The final result is small enough to inspect clearly but interactive enough to make overflow easier to understand.
